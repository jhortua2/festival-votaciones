# Atención a las observaciones de la Entrega 1

| # | Observación del docente | Qué se hizo | Dónde se ve |
|---|---|---|---|
| 1 | Validar si la votación del público será independiente o se combinará con la calificación del jurado; el 70/30 no es una decisión oficial | Cada votación tiene un **modo de resultado** configurable: solo público, solo jurado, **independiente** (por defecto) o **combinado**. El 70/30 se muestra como «Propuesta, no decisión oficial». La decisión sigue como pregunta P-06 para la Fundación | Detalle de la votación, panel de resultados, formulario de votación, `votaciones/models.py` |
| 2 | Incorporar en el modelo conceptual las relaciones de asignación de jurados y los registros de auditoría | El modelo conceptual ahora tiene las entidades **Asignación de jurado** (muchos a muchos entre Votación y Usuario) y **Auditoría** (relacionada con Usuario) | [`modelo-conceptual.png`](modelo-conceptual.png), [`modelo-entidad-relacion.png`](modelo-entidad-relacion.png) |
| 3 | Diferenciar las reglas aprobadas por el cliente de las propuestas, en la documentación y en las interfaces | Cada regla tiene un **origen**: *Enunciado* (definida por el cliente) o *Propuesta* (sugerida por el equipo, pendiente de validación). Las pantallas muestran la etiqueta y una leyenda | `votaciones/reglas.py`, detalle de la votación, README |
| 4 | Facilitar el acceso al repositorio y presentar evidencias reproducibles del funcionamiento y de las pruebas | Repositorio público, sin inicio de sesión. README con el paso a paso (entorno virtual, base de datos, datos de prueba). Las pruebas corren solas en GitHub Actions contra MySQL 8 en cada commit | README, pestaña **Actions**, `.github/workflows/pruebas.yml` |
| 5 | Algunas interfaces no se podían ver porque los enlaces pedían credenciales | El prototipo y los mockups se publicaron en un enlace abierto, sin inicio de sesión, y se verificaron desde una ventana de incógnito | Enlace público del prototipo (en el PDF de la Entrega 2) |
